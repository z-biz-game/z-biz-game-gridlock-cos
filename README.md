# 死锁车库 · GRIDLOCK

把主角车开出停车场。经典 Rush Hour / 塞车时间玩法的浏览器实现，但和纸卡版有两个关键区别：
**每一关的"最少几步"不是印在卡片上的估计值，而是广度优先搜索量出来的确定答案** —— 以及
**这个问题有两个正确答案**。

同一个堵车，两种都算得过去的数法：

- **滑步**：一次拖动不论滑过几格都算一步。这是实体卡片的口径，所以这里的 18 步可以和任何
  一张卡片的 18 步对照。
- **格步**：滑一格算一步，拖三格记三步。

两个数都由搜索量出，而且不是彼此的倍数（计步规则只写在 `js/core/law.js:33` 一处）：64 关里
两者比值中位 1.72、最小 1.00（`kerb-01` 是 4 滑步 / 4 格步）、最大 2.75（`lane-06` 是 8 滑步
/ 22 格步）。两个口径数的是**同一批局面**——一次 3 格拖动恰好是一条长度 3 的格步路径，
所以可达状态集合相同，只是量的尺不同。

`gridlock-01` 因此可以诚实地同时印"最少 18 步"和"最少 31 步"：实测那条 18 拖的路线正好走
31 格（两个数它都打平），而 31 格的路线要花 31 拖（远高于 18）。两个下界各管一件事——
**动手几次**与**总共挪几格**——同一个位置可以同时在两条尺子上到顶，也可以只到一条。

**线上可玩**：<https://z-biz-game.github.io/z-biz-game-gridlock-cos/>

- 零依赖、零美术、零打包器：只有 `index.html` + `css/` + `js/`，浏览器加载的就是仓库里的文件。
- 64 关已烘焙，每关两个数字各由两条独立算法复解。
- 战役 / 每日 / 随机 / 分享链接四种入口，同一个 id 在任何设备上都是同一个局面。
- 本地存档（localStorage），无账号、无网络请求、可离线。

## 跑起来

```bash
node server.cjs            # http://127.0.0.1:5180/
npm run unit               # 七个 node 测试套件，合计 75 条断言、5.8 秒
bash tools/verify.sh       # node 套件 + headless Chrome 真实鼠标键盘验收，六个场景 78 条
npm run bake               # 重新生成 js/data/lots.js（约 5 分钟，见下）
npm run balance            # 生成器体检：接受率、两个数字、耗时（约 3 分钟，实测 2m56s）
npm run scatter            # 反证：随机撒车每档 1 万个的产出（实测 4m21s，见 DESIGN 第 3 节）
npx electron .             # 桌面壳（需先 npm i -D electron）
```

`server.cjs` 是零依赖静态服务器，存在的唯一理由是 ES module 需要一个 origin，`file://` 不行。

## 这一关的两个数字从哪来

游戏里没有手写关卡，也没有"简单/中等/困难"这种标签。链条是这样的：

1. `js/core/make.js:115` 的 `grow` 从主角车开始**生长**：每次加一辆车，立刻用 `js/core/solve.js`
   重测**两个**最短步数，只有把数字推上去的车才留下（推不上去的算作债务，后面还不上就被
   `js/core/make.js:165` 回滚删掉）。
2. `tools/bake.mjs` 在构建期跑它，把每关的 `spec` 序列化，然后**从序列化结果重新解一遍**。
   每个数字走两条互不相同的路：按该口径自己的边走广度优先（`js/core/solve.js:20`），
   在拖动图上按格加权走 Dijkstra（`js/core/solve.js:78`）。两条路对不上就抛错，不降级。
   61/64 关还带一张**逐局面**距离表（`js/core/solve.js:137`）；剩下的 3 关（`lane-06/07/14`）
   可达局面数超过 `tools/bake.mjs:33` 的 40000 预算，只发行起点那两个数字。
3. `test/library.test.mjs` 在每次 CI 里把 `js/data/lots.js` 逐关再解一遍。手改一个 `moves`
   或 `movesCell` 字段，构建就红。

除搜索之外还有一道不依赖搜索的下界：`js/core/law.js:90` 的 `witness` 只数出口那条通道——
主角车自己要走过几格、车头前面钉着几辆车，加起来就是两个数字各自的地板。它能人手数完，
所以任何一条假想的"搜索说这一关 3 步、通道却要 5 步"的路都会在 bake 期被拦下。池子里每一行
都带着这个数（`js/data/lots.js` 的 `witness` 字段）：`gridlock-16` 是 24 滑步 / 47 格步，
通道只逼出 3 / 6 —— 面板就把这个差印成"通道逼出 3／6"（`js/main.js:114`），
剩下的 21 拖与 41 格全是这盘棋逼你绕的路。

所以浏览器永远不生成关卡，只从池子里挑。这不是洁癖：`test/balance.mjs` 实测顶层段位
（死锁）中位数 2.16 秒、最差 14.6 秒、40 个种子里只有 12 个能长出合格关卡。这个成本放在
构建期是免费的，放在玩家点一下屏幕之后是灾难。

## 已烘焙的池子

| 档位 | 棋盘 | 关卡数 | 滑步 | 滑步中位 | 格步 | 格步中位 | 车辆 | 可达局面数 min / med / max |
|---|---|---|---|---|---|---|---|---|
| 巷口 kerb | 5×5 | 16 | 4–5 | 4 | 4–10 | 7 | 5–7 | 9 / 589 / 1192 |
| 单行 lane | 6×6 | 16 | 8–12 | 9 | 11–22 | 17 | 9–10 | 657 / 13198 / 61960 |
| 路口 junction | 6×6 | 16 | 13–17 | 15 | 22–42 | 28 | 10–12 | 1146 / 5380 / 30013 |
| 死锁 gridlock | 6×6 | 16 | 18–24 | 19 | 26–47 | 32 | 10–13 | 344 / 7179 / 21771 |

表里的两列步数区间是从**实际入库的关卡**量出来再写进 `TIERS_META` 的，不是生成器想要的区间。
两者不一致时以入库为准——这一条由 `test/library.test.mjs` 断言。滑步的四档带互不重叠；
**格步的带是重叠的**（lane 上界 22 撞上 junction 下界 22，gridlock 下界 26 落在 junction 的
22–42 之内），因为生成器只按滑步区间停机，第二个数字是顺带量出来的观测值而不是被追的目标。
把格步也做成不重叠的带，需要生成器同时追两个数——那是一件没有做、也没有声称做了的事。

整张表可以用一条命令重新生成，别手改数字：

```bash
node -e "import('./js/core/library.js').then(m => console.log(m.stats()))"
```

难度不止看步数：`局面` 一栏是同一关里 BFS 能走到的不同排列数。20 步但只有 400 个局面的关卡
是练习题，同样的 20 步穿过 2 万个局面才是谜题。两个数都在 `js/data/lots.js` 的每一行里，
和两个步数并排放着。

## 验收

`bash tools/verify.sh` 一条命令跑完两层，全部断言都是可判定的：

- **node 层**（75 条）：`test/lot.test.mjs` 模型与合法拖动、`test/solve.test.mjs` 搜索、
  `test/law.test.mjs` 计步口径、`test/game.test.mjs` 规则、`test/storage.test.mjs` 存档、
  `test/make.test.mjs` 生成器、`test/library.test.mjs` 全池复验。
- **浏览器层**（78 条，6 个场景）：`tools/playtest.mjs` 用 CDP 起一个真实 headless Chrome，
  `@boot` 检查画布真的画出了像素、`@play` 走完通关与评星、`@routes` 覆盖四种路由与越界钳制、
  `@save` 验证 localStorage 落盘与两次点击的清档、`@law` 把两条口径各打满一遍（格步路线确实
  一格一步、滑步路线确实一拖一步，两张通关卡各自三星）、`@pointer` **派发真实鼠标事件**把整条
  最短路线拖完，逐辆核对车停在哪一格，断言八倍过拉的车停在棋盘边界，再用一次真实鼠标点击切到
  格步、`Page.reload` 之后从存档里把偏好读回来。

两套步数期望值不是从被测代码里读出来的：`test/fixture.mjs` 的 CHAIN 关卡 par=3 滑步 / 6 格步
是手算的，`test/solve.test.mjs` 再分别穷举证明"两步拖不完"和"五格走不完"——后者是从
`js/core/lot.js:143` 的 `moves()` 现场枚举单格拖动列出来的，不是调用 `js/core/law.js:41` 的
`eachStep`，否则搜索器就给自己出题再给自己打分。

`@pointer` 这一段还修掉了一条**旧验收自身的漏洞**：原来的过拉参数（3 倍）会让车停在路线要求
之外的格子上，而旧断言只数拖动的次数、不看车停在哪，于是"跟着认证路线拖完"是靠运气绿的。
现在每一步都比对 `pos[car]`，两个账本各自核对总数。

## 规则

- 6×6（入门档 5×5）街区，右侧一个出口，只在出口那一行。
- 一辆琥珀色的主角车是玩家要开走的那辆。
- 车辆只能沿自身轴向滑动，不能旋转、不能重叠、不能出界；灰色方块是混凝土，永久占位。
- 主角车头抵住右侧边界即通关。
- 两个计步口径同时记账：面板上"步数"一栏永远显示 `滑步／格步` 两个数，切换口径只改变
  评星和提示读的是哪一本账，**不重置任何一个计数器**（切换只做一件事：`js/main.js:324`，
  两个计数器由同一批滑动各自入账：`js/core/game.js:56`、`:57`）。评星相对于所选口径自己的
  par（`js/core/game.js:103`）。两条尺子各自有各自的最优路线：`gridlock-01` 那条 18 拖的走法
  恰好也只用 31 格，两边同时三星；`gridlock-16` 最省的 24 拖要走 50 格，所以在格步那一本账上
  是 50／47 —— 两星。**任何一条路线的格数都不低于格步 par、拖数都不低于滑步 par**，这就是
  BFS 最优性的内容：入库前逐关复解（`test/library.test.mjs:23`），线上再由 `@law` 拿页面自己
  搜出来的那条拖动路线现场核对它值几格。

## 已知边界

- 6×6 上 12 辆车左右能长到 22–24 滑步，再往上生成器就交不出货了：顶层段位 40 个种子里只活
  12 个，且 26 步以上实测不可达。想要 30 步以上的关，得换更大的棋盘或者别针式结构，而不是
  把预算调大。（30 步**格步**倒是随处可见——gridlock 档实测 26–47。别把两个口径混着比。）
- 每日关卡是从整个池子里挑的，所以某天可能一上来就是死锁档。这是刻意的：没有账号体系，
  就不做"按进度调节每日难度"这种需要状态的东西。
- 通关后没有彩带、没有音效、没有分享弹窗，只有一个"分享"按钮把 `#/lot/<id>` 链接写进剪贴板。
- 两条口径是**同一个游戏的两个尺子**，不是两种难度、更不是两个模式：没有"格步专属关卡"，
  也不会有需要分别解锁的两条进度线。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高。
- **钉住两个数**：`EXPECT_CHECKS=30`（R 段实际检查的路径条数）与 `EXPECT_ROWS=48`
  （这一次跑的断言条数）。没改页面却掉了，说明解析断了；删掉一张图标会同时少一条 R10 与那张的
  P1/P2，所以两个数一起钉，rows 能漂就是闸在缩水的信号。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸），要求每一刀都让闸**点名**变红；X10 是阴性对照——往入口 JS 追加一行只写在注释里
的假路径，闸必须仍然绿、条数仍然 `30`、rows 仍然 `48`。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑，所以页面改了、仓与仓不同，台架跟着走。

`npm run deploy-set` 与 `npm run deploy-set:selftest` 是同两条命令的本地入口；把它们接进本仓
那条浏览器 one-shot（`tools/verify.sh`）还欠着——那道脚本的腿名单与条数钉是每个仓自己的形状。
